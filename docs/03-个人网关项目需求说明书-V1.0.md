## 1. 文档目的

本文档用于冻结个人网关 V1.0
的产品范围、功能边界、核心数据模型、安全要求、代码复用方案、部署约束及验收标准。后续原型设计、数据库设计、接口设计和正式开发均以本文档为需求基线。

## 2. 项目背景

个人工具通常采用不同的协议和认证方式，例如 REST API、OAuth、IMAP、远程
MCP、EDAM/Thrift 等。直接把 Access Token、Refresh Token、邮箱授权码或
API Secret
存放在大模型侧，会产生凭证泄露、授权范围失控、无法统一吊销和缺乏审计等风险。

本项目建设一个轻量个人网关，在外部工具和 AI 客户端之间建立受控通路：

外部工具 / 个人账号  
↓  
工具与连接注册中心  
↓  
网关运行内核：鉴权、凭证注入、协议执行、结果脱敏  
↓  
AI 客户端、发布与授权中心  
↓  
ChatGPT MCP / GPT Actions / 其他 AI 客户端

所有调用同时写入日志与告警中心，形成可查询、可限流、可吊销、可紧急停用的闭环。

## 3. 产品定位

个人网关是一个轻量的：

> 工具注册表 + AI 访问授权表 + 安全执行代理 + 审计告警中心。

系统不承担大模型推理、对话记忆或复杂工作流编排，也不把外部工具数据全量同步到本地。其核心价值是：

- 统一登记外部工具、账号连接和认证信息；

- 将标准 API、远程 MCP、IMAP 等能力统一抽象为可授权的 Tool；

- 按 AI 客户端选择性发布为 MCP 或 OpenAPI；

- 隔离上游高敏凭证；

- 对每次调用执行权限检查、限流、结果裁剪和审计；

- 提供异常告警和紧急停用能力。

## 4. 建设原则

1\.
注册优先：工具、连接、发布端点和客户端均以注册数据驱动，不逐工具写死路由。

2\. 协议中立：Tool 描述业务能力；上游执行协议和下游发布协议分离。

3\. 一次定义、多端发布：同一 Tool 可同时发布为 MCP Tool 和 GPT
Action/OpenAPI Operation。

4\. 标准能力无代码：普通 REST/OpenAPI、远程 MCP、已支持的 IMAP
连接应通过配置完成接入。

5\. 特殊能力一次扩展：新签名算法开发一次插件，新协议开发一次
Executor，后续同类工具复用。

6\. 最小权限：默认拒绝，V1
默认只读，不开放发送、删除、转账、下单等高风险操作。

7\. 凭证隔离：AI 客户端永远不获取上游真实 Token、授权码或 Secret。

8\. 轻量部署：适配 Vercel Serverless，不依赖常驻进程、Docker
集群或复杂消息队列。

9\. 成熟代码优先：协议、认证、解析、通信、限流和 UI 尽量复用成熟项目。

10\. 移动优先但兼顾后台效率：H5 同时适配 375px 手机和宽屏 PC。

## 5. V1.0 范围

### 5.1 纳入范围

- 单管理员管理后台，邮箱和密码登录；关闭公开注册；V1 不实现 TOTP。

- 工具与连接注册中心。

- AI 客户端、发布端点和授权中心。

- 日志、运行状态与邮件告警中心。

- 通用 RestExecutor、RemoteMcpExecutor、ImapExecutor。

- 印象笔记 EDAM 连接器的最小实现或兼容性适配。

- OpenAPI 文件解析、接口筛选和 Tool 生成。

- 远程 MCP 注册、tools/list 发现和选择性导入。

- 标准 REST Tool 手工配置。

- MCP 动态发布和 OpenAPI 动态发布。

- GPT Action Bearer API Key。

- MCP OAuth 2.1。

- AES-256-GCM 凭证加密。

- Supabase PostgreSQL 审计日志。

- Upstash 限流、连续失败计数、告警去重和幂等状态。

- Resend 邮件告警。

- 全局、客户端、发布端点、工具和连接级紧急停用。

### 5.2 不纳入范围

- 多管理员、多租户和组织管理。

- TOTP、短信二次验证和硬件密钥。

- 面向公众开放或插件市场发布。

- 邮件发送、回复、转发和删除。

- 笔记创建、修改和删除。

- 网盘上传、移动、分享和删除。

- 币安下单、撤单、转账和提现。

- 附件和大型文件中转。

- 全量数据同步、向量数据库和语义索引。

- 工作流编排、工具链自动 chaining 和长任务队列。

- 通用可编程插件市场。

- Redis 作为正式审计日志库。

## 8. 核心对象模型

| **对象**    | **定义**                                       | **示例**                                 |
|-------------|------------------------------------------------|------------------------------------------|
| Connection  | 一个具体外部服务或账号实例                     | 我的 QQ 邮箱、百度网盘账号、币安公共 API |
| Tool        | 协议中立、可被 AI 调用的一项能力               | mail_search_messages、files_search       |
| Executor    | 负责执行某类上游协议                           | RestExecutor、ImapExecutor               |
| Publication | 将一组 Tool 以 MCP 或 OpenAPI 形式发布         | 个人数据只读 MCP、私人 GPT Action API    |
| AI Client   | 具体调用方                                     | ChatGPT MCP、私人 GPT、MCP Inspector     |
| Grant       | AI Client 对 Publication/Tool/Scope 的授权关系 | ChatGPT MCP 可读取邮件和笔记             |
| Credential  | 加密保存的上游认证信息                         | OAuth Token、邮箱授权码、API Secret      |

### 8.1 关键关系

AI Client  
↓ Grant  
Publication（MCP 或 OpenAPI）  
↓ 包含  
Tool  
↓ 使用  
Connection + Executor  
↓ 调用  
外部服务

上游协议与下游协议必须分离：一个通过 REST 执行的 Tool，可以同时发布为
MCP 和 OpenAPI；一个远程 MCP Tool，也可以被网关重新发布到另一个受控 MCP
Publication。

# 9. 模块一：工具与连接注册中心

## 9.1 连接管理

系统应支持以下连接类型：

| **连接类型** | **V1 能力**                              |
|--------------|------------------------------------------|
| REST/API     | 基础 URL、认证、Header、超时、域名白名单 |
| Remote MCP   | MCP 地址、传输方式、认证、工具发现       |
| IMAP         | 主机、端口、TLS、账号、授权码、连接模板  |
| EDAM         | 印象笔记专用最小连接器                   |

### 9.1.1 邮箱模板

至少内置：

- QQ 邮箱；

- 163 邮箱；

- 通用 IMAP。

新增同类邮箱时，只增加 Connection 或模板配置，不新增邮件搜索代码。

### 9.1.2 连接状态

- 草稿；

- 正常；

- 异常；

- 凭证即将过期；

- 凭证失效；

- 已停用。

连接页面支持新增、编辑、测试、启停、更新凭证和查看最近错误。

## 9.2 凭证管理

- 使用 AES-256-GCM 应用层加密；

- 主密钥仅存放于 Vercel Sensitive Environment Variable；

- 每条凭证独立随机 IV；

- 数据库存储密文、IV、认证标签和密钥版本；

- 保存后不回显完整明文；

- 浏览器、日志和 AI 响应不得包含凭证；

- 解密仅发生于服务端执行期间；

- 支持覆盖、删除、到期时间和后续密钥轮换。

## 9.3 Tool Registry

每项 Tool 至少包含：

id、name、display_name、description、category、version、enabled  
input_schema、output_schema  
executor_type、connection_id、executor_config  
required_scopes、risk_level、read_only  
created_at、updated_at

Tool 必须使用稳定唯一名称，公开名称和说明可在 Publication 中覆盖，但内部
ID 不随展示名称变化。

## 9.4 手工注册 REST Tool

表单支持：

- HTTP 方法；

- 基础 URL 和路径模板；

- Path、Query、Header、Body 参数映射；

- 固定 Header；

- 输入和输出 JSON Schema；

- 响应字段提取与裁剪；

- 超时、最大响应大小和有限重试；

- 认证引用；

- Scope、风险等级和只读属性。

普通 REST Tool 必须由通用 RestExecutor 执行，不得逐接口手写独立 MCP
Handler。

## 9.5 OpenAPI 导入

流程：

上传或填写 OpenAPI 文档  
→ 安全校验与解引用  
→ 展示 Operation 列表  
→ 勾选允许导入的接口  
→ 自动生成 Tool 草稿  
→ 人工确认名称、说明、风险、Scope 和连接  
→ 测试  
→ 启用

要求：

- 不自动开放全部接口；

- 默认排除删除、转账、发送、上传等高风险操作；

- OperationId 缺失时生成稳定名称；

- 解析失败时提供明确错误；

- 导入结果为数据库 Tool 记录，而不是为每个产品生成独立项目。

## 9.6 远程 MCP 注册

流程：

填写 MCP 地址和认证  
→ 连接测试  
→ tools/list 自动发现  
→ 显示名称、说明和 Schema  
→ 管理员勾选  
→ 导入 Tool Registry

远程 MCP 的上游凭证由网关保存；AI 客户端不直接接触上游 MCP 凭证。

## 9.7 API 转 MCP

API 转 MCP 是工具侧配置能力和运行内核共同实现的功能：

- 工具注册中心保存 REST 方法、参数映射、Schema、连接和认证引用；

- 运行内核使用通用 RestExecutor 将 tools/call 转换为 HTTP 请求；

- AI 接入模块决定该 Tool 是否加入某个 MCP Publication。

运行链：

MCP tools/call  
→ Publication 查找公开工具  
→ Tool Registry 读取执行配置  
→ PolicyGuard 鉴权  
→ RestExecutor 构造 HTTP 请求  
→ CredentialService 注入凭证  
→ 上游 API  
→ ResultSanitizer 转换与脱敏  
→ MCP 结果

无代码边界：

| **场景**             | **是否改代码**      |
|----------------------|---------------------|
| 标准 OpenAPI REST    | 否，配置导入        |
| 普通 REST 无 OpenAPI | 否，表单配置        |
| 现有远程 MCP         | 否，自动发现        |
| 已支持的 IMAP 邮箱   | 否，新增连接        |
| 新的签名方式         | 只开发一次认证插件  |
| 新的网络协议         | 只开发一次 Executor |
| 多步复杂业务         | 可能开发组合 Tool   |

## 9.8 Tool 测试

- 输入测试参数；

- 展示脱敏后的上游请求摘要；

- 展示脱敏响应、耗时和错误分类；

- 支持保存为草稿或启用；

- 测试不得把正文、Token 或完整个人数据写入日志。

# 10. 模块二：AI 客户端、发布与授权中心

## 10.1 Publication Registry

Publication 表示一组向外发布的工具，类型为：

- MCP；

- OpenAPI/REST。

每项 Publication 包含：

- 名称、Slug、类型和状态；

- 工具清单；

- 公开名称和公开说明；

- 认证要求；

- 默认 Scope；

- 限流和响应上限；

- 创建时间和最后调用时间。

## 10.2 MCP Publication

建议路径：

/api/mcp/{publication_slug}

要求：

- 动态根据 Publication 返回 tools/list；

- tools/call 进入统一 executeTool()；

- 使用 OAuth 2.1；

- 支持按客户端过滤可见 Tool；

- 所有 V1 Tool 默认 readOnlyHint: true；

- 支持停用整个端点。

## 10.3 OpenAPI Publication

建议路径：

/api/actions/{publication_slug}/{tool_name}  
/openapi/{publication_slug}.json

要求：

- 根据同一 Tool Schema 动态生成 OpenAPI；

- 使用 Bearer API Key；

- 与 MCP 共用统一执行逻辑；

- 不为 Action 再写一套业务处理函数。

## 10.4 AI Client Registry

字段包括：

- 名称；

- 类型：GPT Action、ChatGPT MCP、测试客户端、其他 MCP；

- 认证方式；

- 状态；

- 最后调用时间；

- 调用限额；

- 备注。

## 10.5 客户端授权

授权关系支持：

- 客户端访问一个或多个 Publication；

- Publication 内按 Tool 进一步限制；

- Scope 限制；

- 到期时间；

- 允许调用时段；

- 每分钟、每日和单 Tool 限额；

- 随时撤销。

默认拒绝。Token 中包含 Scope
仍不足以直接执行，还必须检查客户端、Publication、Tool 和 Connection
的实时状态。

## 10.6 GPT Action API Key

- 使用高强度随机值；

- 明文只在创建时显示一次；

- 数据库只保存哈希和前缀；

- 支持到期、轮换、吊销和短期新旧并行；

- 每个 AI Client 使用独立 Key。

## 10.7 MCP OAuth 2.1

- 使用 Supabase OAuth 2.1 Server；

- Authorization Code + PKCE；

- Access Token 和 Refresh Token；

- 每次请求校验签名、iss、aud/resource、exp、客户端、用户和 Scope；

- 管理后台支持查看和撤销授权；

- V1 不要求 TOTP。

## 10.8 紧急停用

支持：

- 全局停止全部 AI 调用；

- 停止全部 MCP；

- 停止全部 Action；

- 停止单个 Publication；

- 停止单个 AI Client；

- 停止单个 Tool；

- 停止单个 Connection；

- 吊销 Key 或 OAuth Grant。

# 11. 模块三：日志、运行状态与告警中心

## 11.1 审计日志

正式审计日志存入 Supabase PostgreSQL，记录：

- request_id、trace_id；

- AI Client、Publication、Tool、Connection；

- 接入协议；

- 时间、耗时、成功状态；

- HTTP/MCP 状态；

- 返回记录数；

- 错误类型和风险等级；

- 是否触发告警。

不记录：

- 邮件或笔记正文；

- Token、授权码和 Cookie；

- Authorization Header；

- 完整个人邮箱地址和文件路径；

- 默认完整搜索关键词。

## 11.2 日志查询

支持按时间、客户端、Publication、Tool、Connection、成功状态、风险等级和错误类型筛选；支持查看单条调用链和导出脱敏
CSV。

调用日志默认保留 90 天，安全事件默认保留 180 天。

## 11.3 Upstash 用途

Upstash Redis 仅用于：

- 限流计数；

- 连续失败次数；

- 告警去重；

- 幂等键；

- 短期异常状态；

- 未来一次性确认令牌。

Upstash 不作为唯一审计日志库。

## 11.4 异常规则

V1 使用固定规则：

- 连续认证失败；

- 使用已撤销 Key 或 Grant；

- 请求未授权 Tool 或 Scope；

- 超过限额；

- 非常用时段调用；

- 上游连续失败；

- 凭证即将过期或已经失效；

- 单次响应异常过大；

- 客户端、Publication、连接或总闸被修改。

## 11.5 Resend 邮件告警

- 正式联调前由用户注册 Resend；

- 配置并验证发件域名；

- API Key 只存于 Vercel 环境变量；

- 告警邮件只包含事件摘要、风险等级和处理建议；

- 不包含正文、Token 或完整个人数据；

- 发送失败写入 alert_deliveries 并可重试。

## 11.6 健康检查

每日检查：

- Connection 连通性；

- Token 到期；

- IMAP 登录；

- MCP 上游发现；

- Resend 发送配置；

- 未处理高风险事件；

- 过期日志清理。

# 12. 网关运行内核

## 12.1 统一执行入口

所有 MCP 和 Action 请求必须进入：

executeTool(toolId, input, requestContext)

禁止为 MCP 和 OpenAPI 分别维护业务逻辑。

## 12.2 核心组件

| **组件**          | **职责**                                                    |
|-------------------|-------------------------------------------------------------|
| RequestContext    | 请求 ID、用户、客户端、Publication、Scope、Tool、Connection |
| ToolResolver      | 查询并解析 Tool 和 Publication 配置                         |
| PolicyGuard       | 校验状态、Scope、时段、限流和全局开关                       |
| CredentialService | 解密和短暂提供上游凭证                                      |
| ExecutorRegistry  | 按 executor_type 选择执行器                                 |
| ResultSanitizer   | 裁剪、脱敏、格式转换和提示注入隔离                          |
| AuditWriter       | 写入审计日志和安全事件                                      |

## 12.3 执行器

V1：

- RestExecutor；

- RemoteMcpExecutor；

- ImapExecutor；

- EdamExecutor（最小实现）。

预留：

- SignedRestAuthPlugin；

- SmtpExecutor；

- WebSocketExecutor。

# 13. 首批外部能力

| **类别**  | **首批 Tool**                              | **权限** |
|-----------|--------------------------------------------|----------|
| 邮件      | 列出文件夹、搜索邮件、读取正文和附件元数据 | 只读     |
| 笔记      | 列出笔记本、搜索笔记、读取笔记             | 只读     |
| 文件      | 列目录、搜索文件、读取元数据               | 只读     |
| 标准 REST | 由管理员注册的低风险接口                   | 默认只读 |
| 远程 MCP  | 管理员筛选后导入的低风险工具               | 默认只读 |

V1 不向 AI 发布 SMTP 发送能力。邮件告警使用 Resend，与个人邮箱连接分离。

# 16. 安全需求

1\. 全站 HTTPS、Secure/HttpOnly Cookie、严格 CORS。

2\. 关闭公开注册，管理员邮箱白名单。

3\. V1 不实现 TOTP，但敏感操作要求重新输入密码。

4\. 所有输入使用 Zod/JSON Schema 校验，拒绝未知字段。

5\. 外部请求只允许预设域名，禁止任意 URL 和 SSRF。

6\. 邮件、笔记和文件内容均视为不可信数据，不得改变 Scope
或触发额外工具。

7\. 不自动访问内容中的 URL、远程图片或脚本。

8\. 凭证、Key 和正文不得进入 Pino、Vercel 和审计日志。

9\. 默认只读；所有写操作均留到后续版本并配套实时确认。

10\. 全局 Kill Switch 始终可用。

# 17. 非功能需求

| 数据     | Supabase PostgreSQL；持久状态不得只保存在函数内存       |

| 超时     | 所有上游调用必须设置超时；瞬时错误最多重试一次          |
| 可维护   | 依赖锁定精确版本；数据库通过 Migration 管理             |
| 测试     | Vitest 单元测试、Playwright 响应式和关键流程测试        |
| 浏览器   | 当前主流 Chrome、Edge、Safari 移动端                    |
| 可访问性 | 表单标签、键盘操作、焦点管理、足够点击区域              |

# 20. 验收标准

## 20.1 工具与连接

- 可注册普通 REST、OpenAPI、远程 MCP 和 IMAP 连接；

- 163 邮箱只增加连接，不改邮件 Tool 代码；

- OpenAPI 可筛选并生成 Tool 草稿；

- 远程 MCP 可发现并导入工具；

- 凭证不回显、不入日志。

## 20.2 API 转 MCP

- 一个标准 REST Tool 不编写专用 MCP Handler；

- tools/list 根据 Publication 动态生成；

- tools/call 使用通用 RestExecutor；

- 同一 Tool 可同时通过 MCP 和 OpenAPI 调用，结果逻辑一致。

## 20.3 AI 接入

- GPT Action 可通过独立 API Key 调用；

- ChatGPT MCP 可完成 OAuth 授权；

- 客户端只能看到和调用获授权工具；

- 撤销、停用和总闸立即生效。

## 20.4 日志与告警

- 每次调用产生脱敏审计日志；

- Upstash 限流生效；

- 越权、连续失败和凭证异常可产生安全事件；

- Resend 可发送脱敏告警。

## 20.5 UI 与部署

- 375、768、1024、1440 四档可用；

- PC 表格有手机卡片对应视图；

- GitHub 分支提交触发 Vercel Preview；

- main 分支可稳定生产部署；

- 构建、类型检查和关键测试通过。

# 21. 主要风险

|-------------------------------|--------------------------------------------|
| MCP SDK与mcp-handler更新快    | PoC后锁精确版本，建立回归测试              |
| Supabase OAuth能力变化        | 封装认证适配层，保留替换可能               |
